# MyBatis SQL Tester

> 扫描 MyBatis Mapper，自动生成覆盖**全部动态 SQL 分支**的测试参数，用 MyBatis 原生引擎渲染出真实 SQL，并在目标数据库上安全执行（默认回滚）。

面向**数据库迁移 / 升级 / 换库**场景：在改表、换库（如 MySQL 5.7 → 8.0、Oracle → 达梦）之前，把存量 Mapper 的所有分支都跑一遍，提前暴露方言不兼容、非法 SQL、参数类型不匹配等问题，而不是等上线后靠日志猜。

## 背景

MyBatis 的 `<if>` / `<choose>` / `<foreach>` 让一条 SQL 实际有 **2^N 种形态**。迁移验证时手工构造参数既繁琐又容易漏：

- 漏掉某个 `<if>` 为 false 的分支 → 上线才发现该形态 SQL 非法；
- 参数类型靠猜（`#{id}` 到底是 Long 还是 String）→ 目标库类型严格时报错；
- 改完 SQL 无法快速回归。

本工具把这件事自动化：

1. 扫描 Mapper XML + Mapper 接口，推断每个参数的真实 Java 类型；
2. 对每个动态分支做**约束求解**，生成能命中该分支的参数值（并用 MyBatis 的 OGNL 引擎校验）；
3. 用 **MyBatis 自身的 `XMLScriptBuilder` / `BoundSql`** 渲染 SQL（保证与线上渲染逻辑一致）；
4. 用 MyBatis 的 `ParameterHandler` 绑定参数，在目标库执行，**默认回滚**，不写脏数据。

---

## 特性

- **零侵入**：只读源码与 XML，不需要启动业务应用，不依赖 Spring 容器。
- **真实渲染**：直接复用 MyBatis 3.5.13 解析 XML 动态标签，`<where>` / `<set>` / `<trim>` / `<include>` / `<foreach>` 语义与线上完全一致。
- **分支持久化**：`<if>` T/F、`<when>`、`<otherwise>`、`<foreach>` 非空/空，共 5 类覆盖点全部建模。
- **自动求值校验**：生成的每个参数集都会用 MyBatis 的 `DynamicContext + OgnlCache` 复盘，覆盖不到的分支会明确报告。
- **用例合并**：互不冲突的覆盖点会合并成同一条用例，减少执行次数；冲突（同一 `<if>` 同时要求 T/F）绝不合并。
- **人工兜底**：复杂表达式求解不了时，界面直接给出该分支，填一次参数即可，结果按分支持久化。
- **安全执行**：默认 `rollback`；确认无误后可勾选"提交事务"；结果集最多展示 100 行。
- **多目标库**：任意 JDBC 驱动（达梦、Oracle、PostgreSQL、SQL Server…），驱动 jar 可按需加载。
- **决策库**：参数类型、手工分支参数、数据库配置按项目存入 SQLite（`~/.mybatis-sql-tester/<项目名>.sqlite`），可复用、可提交给同事。

## 快速开始

### 环境

| 依赖 | 版本 |
| --- | --- |
| JDK | 8+（编译目标 1.8） |
| Maven | 3.6+ |

### 编译与运行

```bash
mvn clean package -DskipTests
java -jar target/mybatis-sql-tester.jar
```

浏览器打开 <http://localhost:8777>（端口见 `src/main/resources/application.properties`）。

### 立即体验（自带示例）

仓库内置示例工程 `sample/`（7 条语句，覆盖 `<if>` / `<choose>` / `<foreach>` / `<include>` / 正则 / Map 参数）：

1. 「项目扫描」页填写项目根路径：`<仓库绝对路径>/sample`，点击 **开始扫描**；
2. 切到「测试 SQL」页，点击 **重新生成** —— 应显示 `共 17 个分支覆盖点，0 个未自动满足`；
3. 在「目标数据库」页配置一个测试库，回到「测试 SQL」页点击 **在目标库执行全部语句**。

示例库建表语句（以 H2 为例）：

```sql
CREATE TABLE t_user (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  user_name VARCHAR(50),
  age INT,
  email VARCHAR(100),
  create_time TIMESTAMP
);
```

> 目标库请务必使用**测试库 / 只读副本**；工具虽默认回滚，但 DDL 类语句与部分驱动仍可能产生副作用。

## 使用流程

### 1. 项目扫描

输入项目根路径（递归扫描其中所有 `.xml` 与 `.java`），可选输入项目名（决定决策库文件名，留空取目录名）。

扫描结果包含：

- 语句数量、XML 文件数量、决策库路径；
- 每条语句的参数、Java 类型、类型来源（`USER` / `JDBC_TYPE` / `SOURCE` / `HEURISTIC` / `IMPLICIT` / `UNKNOWN`）；
- 待确认类型列表 `pendingTypes`（无法自动推断的参数）。

**类型推断优先级**：

1. 人工确认（从 SQLite 读回，来源标记 `USER`）；
2. `#{id,jdbcType=BIGINT}` 这类显式 `jdbcType`（`JDBC_TYPE`）；
3. Mapper 接口方法签名（`@Param` 名、单参数对象属性、`paramN` 序号）与 POJO 字段（`SOURCE`，支持嵌套对象字段、父类继承字段、`List<User>` 等泛型集合元素字段）；
4. 启发式推断：按分支表达式中的用法（与数字比较→整数、与字符串比较→`String`）及命名约定（`*Id`→`Long`、含 `time`/`date`→`Date`）（`HEURISTIC`）；
5. 仍无法判断 → `UNKNOWN`，进入「参数确认」页。

### 2. 参数类型确认

「参数确认」页只展示**无法推断**的参数（如 `${}`、Map 的未知 key、多参数方法未加 `@Param`）。

- 普通参数：选择或输入 Java 类型，下拉项包含常用标量类型与项目内扫描到的类名，也可手动输入自定义类型；
- `List` / `Set` 等集合参数：先选集合类型，再选元素类型（如 `List` + `Long` → `List<Long>`）；
- `<foreach>` 的 item 参数：只需选择元素类型。

选择一次后写入 SQLite（`param_type` 表），后续扫描自动套用，来源标记为 `USER`，并立即参与测试用例生成。

### 3. 生成测试 SQL 并执行

- **重新生成**：对每条语句求解全部覆盖点，展示用例名称、参数、提示（note）、渲染 SQL；
- **未决分支**：求解不了的分支会在页面上单独列出，填写 JSON 参数（如 `{"userName":"abc"}`）后保存，再点重新生成即可；
- **在目标库执行**：可整体执行，也可只执行某条语句；勾选"提交事务"则落库，否则（默认）回滚。

## 工作原理

```
┌────────────────┐        ┌──────────────────────┐
│ Mapper XML     │        │ Mapper 接口 / POJO   │
│ (if/choose/...)│        │ (@Param、泛型、字段) │
└───────┬────────┘        └──────────┬───────────┘
        │ XmlScanner                 │ InterfaceScanner (JavaParser)
        ▼                            ▼
  语句 / 参数 / 分支            参数名 + Java 类型 + POJO 字段索引
        └──────────────┬─────────────┘
                       ▼
              TypeResolver（类型推断 + 人工确认）
                       ▼
              BranchSolver（把分支转成约束，解出参数值，
                            用 MyBatis DynamicContext + OGNL 校验）
                       ▼
              TestCaseGenerator（合并兼容用例、复核真实覆盖率）
                       ▼
              SqlRenderer（净化 XML → MyBatis XMLScriptBuilder → BoundSql）
                       ▼
              JdbcExecutor（MyBatis ParameterHandler 绑参 → 执行 → 回滚/提交）
```

设计要点：

- **渲染必须真实**：工具把 XML 复制一份并做「净化」——`resultType`/`parameterType`/`javaType`/`typeHandler` 替换成通用类型——再交给 MyBatis 的 `XMLScriptBuilder`，因此 `#{}` 解析、`<where>` 前缀裁剪、`<foreach>` 展开全部由 MyBatis 完成，不存在"自己实现一套导致结果偏差"的问题。
- **校验必须闭环**：求解出的参数值必须能被 OGNL 真实求值为期望的布尔值，否则该分支记为未决，绝不"假装覆盖"。
- **覆盖率是算出来的**：生成后会再次用 OGNL 回放每个用例，统计真实命中的分支，而不是简单相信用例标签。

## 支持的动态 SQL 与表达式

### 标签

| 标签 | 处理方式 |
| --- | --- |
| `<if test>` | 覆盖 T / F 两侧 |
| `<choose>` / `<when>` / `<otherwise>` | 每个 `<when>` 命中一次（前序 when 需为 false），`<otherwise>` 命中一次（全部 when 为 false） |
| `<foreach collection item>` | 覆盖非空 / 空集合；`#{item}` 自动归属到对应 collection |
| `<include refid>` / `<sql>` | 跨文件展开，支持 `别名.id` 引用 |
| `<where>` / `<set>` / `<trim>` | 参数与分支递归收集，渲染交给 MyBatis 原生处理 |

### 表达式（可自动求解）

| 类别 | 示例 |
| --- | --- |
| 空值判断 | `x != null`、`x == null` |
| 相等 / 不等 | `x == 1`、`x != 'abc'`、`x == "A"` |
| 数值比较 | `age > 0`、`age >= 18`、`age < 60`、`age <= 100` |
| 逻辑组合 | `a != null and b > 0`、`x == 1 or y == 2`（支持括号） |
| 字符串空判断 | `name != ''`、`name == ''`、`list.size() > 0`、`list.isEmpty()`、`str.length() > 0` |
| 字符串方法 | `name.contains('a')`、`startsWith`、`endsWith`、`name.matches('.*test.*')` |

不在上表中的表达式（如自定义方法、复杂三元、`@class@method()`）会进入**未决分支**，由人工填参。

### 参数类型来源

| 来源 | 说明 |
| --- | --- |
| `XML jdbcType` | `#{id,jdbcType=BIGINT}` → `Long`；`INTEGER`→`Integer`、`DECIMAL`→`BigDecimal`、`TIMESTAMP`→`Date`、`VARCHAR`→`String`、`BLOB`→`byte[]` 等 |
| Mapper 接口 | 解析方法签名：`@Param` 名优先，否则用 Java 形参名；多参数时可用 `#{param1}` 按顺序匹配；保留泛型（`List<Long>`） |
| POJO | 类字段 + getter，用于推断 `#{userName}` 的归属与类型 |
| 启发式推断 | 依据分支表达式中的用法与命名约定（`*Id`→`Long`、含 `time`/`date`→`Date`） |
| 人工确认 | 界面选择后持久化 |

根参数在运行时用 `Map` 替身构造（POJO 也映射为 Map），因此不依赖业务类是否在 classpath。

## 用例生成规则

| 覆盖点 | 要求 |
| --- | --- |
| `<if>` | 一条用例命中（T），一条用例跳过（F） |
| `<when>` | 命中；且**同组前序 when 全为 false** |
| `<otherwise>` | 同组所有 when 全为 false |
| `<foreach>` | 集合非空 / 集合为空各一条 |

生成流程：

1. 为每个覆盖点构造约束列表；
2. 逐个求解（可用样例值作基线，逐条收紧约束）；
3. 与已有用例尝试**合并**（合并后重新求解，能解才合并；同分支 T/F 冲突直接拒绝）；
4. 用真实 OGNL 回放复核，覆盖不到的分支写入 `unresolvedBranches`。

对空集合 `<foreach>`，工具会额外提示：MyBatis 会直接跳过内容，可能生成非法片段（如 `WHERE id IN`），这属于 mapper 自身缺陷。

## 在目标库执行

「目标数据库」页配置：

| 字段 | 说明 |
| --- | --- |
| 驱动类名 | 如 `dm.jdbc.driver.DmDriver`、`com.mysql.cj.jdbc.Driver`、`oracle.jdbc.OracleDriver` |
| JDBC URL | 目标库地址 |
| 用户名 / 密码 | 数据库账号 |
| 驱动 jar | 可选，逗号/分号分隔的 jar 路径；H2、MySQL 驱动已内置 |

执行行为：

- 使用 MyBatis `ParameterHandler` 绑定参数（与线上一致的 TypeHandler 选择）；
- `autoCommit=false`，**默认执行后回滚**；勾选"提交事务"或传 `"commit": true` 才提交；
- SELECT 返回列名与前 100 行；DML 返回影响行数；同时返回耗时。

> 提示：执行失败往往才是价值所在——例如 `CONCAT`、`IFNULL`、`DATE_FORMAT` 在达梦/Oracle 上不存在，`<set>` 全空导致 `UPDATE t SET WHERE`，空 `<foreach>` 产生 `IN` 无括号等，都是迁移必改点。

## 决策库

按项目名存放于 `~/.mybatis-sql-tester/<项目名>.sqlite`（可用 `mst.decisions-dir` 属性改目录）：

| 表 | 内容 |
| --- | --- |
| `param_type` | 人工确认的参数类型（`stmt_id + param_name` 为主键） |
| `branch_param` | 未决分支的手工参数 JSON（键为覆盖点 id，如 `namespace.id#if1#T`） |
| `db_config` | 目标数据库配置（单行） |

想清空某个项目的全部决策：删除对应的 `.sqlite` 文件后重新扫描。

## HTTP API

所有接口均为 `POST`（除 `GET /api/db-config`），JSON 请求/响应。

### `POST /api/scan`

```json
{ "projectPath": "/path/to/project", "projectName": "demo" }
```

返回：`projectName`、`sqliteFile`、`xmlCount`、`statementCount`、`statements`、`pendingTypes`、`unresolvedBranches`。

### `POST /api/param-type`

```json
{ "stmtId": "com.example.UserMapper.selectById", "paramName": "id", "javaType": "Long" }
```

### `POST /api/branch-params`

为求解不了的分支手工指定参数（`branchId` 用覆盖点 id，即 `unresolvedBranches[].unitId`）：

```json
{
  "stmtId": "com.example.UserMapper.search",
  "branchId": "com.example.UserMapper.search#if1#T",
  "params": { "userName": "manual-value" }
}
```

### `POST /api/generate`

无需参数，按当前扫描结果生成全部用例并渲染 SQL。

返回：`statements`（含 `coverageUnits`、`testCases`、`renderedSql`）、`unresolvedBranches`。

### `POST /api/test`

```json
{ "stmtId": "com.example.UserMapper.selectById", "commit": false }
```

`stmtId` 省略则执行全部语句；`commit` 默认 `false`（回滚）。

### `GET/POST /api/db-config`

```json
{
  "driverClass": "com.mysql.cj.jdbc.Driver",
  "jdbcUrl": "jdbc:mysql://127.0.0.1:3306/demo",
  "username": "root",
  "password": "***",
  "driverJars": "/opt/drivers/DmJdbcDriver18.jar"
}
```

> 决策库以明文保存数据库密码，请勿将 `~/.mybatis-sql-tester/*.sqlite` 传到公开仓库。

## 已知限制

- 仅扫描 **XML Mapper**；注解式 `@Select/@Update` 暂不支持。
- 表达式求解器覆盖常见比较/空值/逻辑组合/字符串方法，其余进入人工填参。
- 不加载业务自定义 `TypeHandler`；渲染时按 `jdbcType` + 运行时值选择内置 handler，必要时可人工指定参数类型。
- 不处理 `<bind>`、`<selectKey>`、`databaseId` 多库差异、存储过程。
- 结果集最多取 100 行；不做结果断言（只验证 SQL 可执行）。
- 缺少数据库实例时无法做真实执行，只能生成与静态校验 SQL。

## FAQ

**Q：为什么 `status == 'A'` 生成的是字符而不是字符串？**
OGNL 把单引号单字符解析为 `char`，比较时会把另一侧转成数字，因此必须给 `Character` 值才能命中；真实 MyBatis 运行时同样如此。若参数实际是 `String`，业务表达式写成 `status == "A"` 更稳妥（工具会给出提示）。

**Q：为什么 `<foreach>` 空集合会产生非法 SQL？**
MyBatis 对空集合直接跳过内容，`WHERE id IN` 后面就没有了。这是 mapper 本身的缺陷，工具会提示；建议业务加 `<if test="ids != null and ids.size() > 0">` 兜底。

**Q：为什么 `<set>` 全空时出现 `UPDATE t SET WHERE ...`？**
同上，`<set>` 会裁掉尾部逗号与 SET 关键字，全空时只剩 `WHERE`。属于 mapper 缺陷，建议保证至少一个字段或加 `<where>` 兜底。

**Q：执行时报函数不存在（如 `CONCAT`）？**
说明源库方言在目标库不存在，正是迁移需要改的点；可将目标库换成同源库验证生成逻辑，或直接作为迁移清单记录。

**Q：能接入 CI 吗？**
可以：`mvn test` 已可独立运行；如需对指定库做回归，可用脚本调用 `/api/scan` → `/api/generate` → `/api/test`，根据返回的 `success/error` 做门禁。
